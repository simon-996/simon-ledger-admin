# 云端账号彻底删除设计

日期：2026-09-28

## 目标与边界

管理员在后台按用户 UUID 删除普通 App 账号。删除只作用于云端：清除线上账号资料和登录态，处理该账号在所有云端账本中的关系。其他用户共享账本中的历史流水、分摊和参与人名称继续保留。手机上未上传的本地账本与流水不在后台可见或可删除范围内。

“彻底删除账号信息”指账号实体及其邮箱、手机号、密码、个人头像和账号关联。共享账本里的参与人名称属于保留的历史账务信息，可能仍能让其他成员认出原用户；这是为了满足保留流水和普通参与人的要求。

本规格只覆盖账号彻底删除。后台对单个账本或流水执行删除、恢复的功能单独设计与实现。

## 管理员操作

1. 在用户列表进入删除预览。预览显示账号标识、拥有的账本、加入但不拥有的账本、每本账本的有效成员、将保留和将删除的数据数量。
2. 对每本仍有其他有效成员的自有账本，管理员从有效成员中指定接手人。只有一名候选人时可以预选，但确认页仍显示其姓名与账号。没有其他有效成员的自有账本标记为“整本云端删除”。
3. 确认页逐本展示接手人及影响范围，管理员输入目标用户 UUID 后提交。提交时服务端重新检查所有权、成员资格和预览时的关系；有变化则拒绝执行并要求重新预览。
4. 成功后用户从列表消失，后台只保留一条不含邮箱、手机号、昵称或原用户 UUID 的删除操作摘要，包含管理员、时间及处理数量。

## 数据处理规则

### 加入别人的账本

- 物理删除目标账号的 `ledger_member` 行，包括已软删除的历史成员行。
- 将目标账号关联的 `ledger_person.linked_user_id` 置空，使其成为普通参与人。保留参与人 UUID、名称、分摊关系和历史流水；清除从账号资料复制来的头像，避免残留账号头像链接。
- 保留流水金额、内容、付款参与人和参与人分摊。流水中的创建人或修改人若指向目标账号，解除该账号引用，并在界面显示“已注销用户”。不把这些流水错误归到别的用户名下。
- 删除目标账号创建的、位于这些账本中的邀请；保留账本变更序列，但解除变更日志中指向目标账号的操作者引用。
- 为成员移除、参与人解绑和必要的账本元数据变化记录增量变更，使其他成员的客户端能刷新数据。

### 目标账号拥有的账本

- 若存在其他有效成员，按管理员在预览中选定的接手人，在同一事务中更新 `ledger.owner_user_id` 和接手成员的角色为 `owner`；删除原所有者成员关系。历史流水和参与人按上节规则保留。
- 若不存在其他有效成员，物理删除整个云端账本及全部关联数据，包括已经软删除的成员、参与人、流水、分摊、邀请和变更日志。按外键依赖顺序删除，不依赖数据库自动级联。
- 已软删除的自有账本也纳入预览，并直接彻底清理；已删除账本不再转交。仅未删除账本的有效成员可以接手，避免留下无所有者的账本。

### 账号本身

- 删除目标账号的幂等请求记录，并解除所有仍保留的流水、参与人、账本和变更日志中的账号外键引用，然后物理删除 `user_account` 行。
- 将 `ledger_transaction.created_by_user_id` 与 `ledger_change_log.operator_user_id` 改为可空；`last_modified_by_user_id` 与 `ledger_person.linked_user_id` 已可空。更新读取接口、变更日志的空操作者处理和 Flutter 端显示逻辑，使匿名历史记录保持可读。
- 删除完成后撤销该账号的 Sa-Token 登录态；普通 App 接口还应验证账号仍存在，使旧 token 不能继续写入。后台管理员登录态保持独立。
- 当前在线数据库和活动会话是本功能清除范围。已有离线设备数据、历史服务器日志及数据库备份的清理取决于各自保留策略，不由后台请求即时清除。

## 接口与一致性

- `GET /api/admin/users/{uuid}/deletion-preview` 返回影响范围、候选接手人和用于防止预览过期的快照标识。
- `DELETE /api/admin/users/{uuid}` 接收每本需要转交的账本 UUID 与接手用户 UUID，以及预览快照标识。服务端验证后台登录态、目标 UUID、所有接手人和当前快照；不接受前端提供的影响数量作为删除依据。
- 数据库清理在单一事务内进行。锁定目标账号和受影响账本，按固定顺序处理；任何一步失败则回滚，不能出现账号已删但账本无所有者的中间结果。事务成功后撤销 token。若会话撤销失败，账号存在性校验仍阻止旧会话访问，并记录待重试的运维错误。
- 后台审计记录在成功提交后写入，不保存目标账号的个人资料或原 UUID。失败请求记录错误类型和管理员，不记录用户敏感资料。

## 验收条件

- 独立账号：账号与其唯一自有账本全部物理删除，其他用户数据不受影响。
- 加入别人账本：账号消失，成员关系消失；参与人变为未绑定状态，原有流水和金额不变，客户端能看到更新。
- 拥有共享账本：每本账有且仅有一个有效 owner，所选接手人拥有账本；其他成员及历史数据保留。
- 多本账本、已软删除记录、本人创建的邀请和他人账本中的历史流水均处理干净，账号外键无残留。
- 候选接手人已退出、预览过期、并发修改或任一删除步骤失败时，整个删除回滚并返回可理解的错误。
- 删除后旧 token 不能调用普通 App 接口；后台审计能查到删除事件但不能恢复目标账号个人资料。
- 自动化测试覆盖上述场景，并检查数据库外键、变更序列与 Flutter 对匿名流水创建人的显示。
